## 4. Counterfactual Pass

For each major Authored Extension, three realistic failure modes:

1. **§22.10.3.A Per-Org Concurrency Lock.** (a) Convex serializable-transaction OCC retry storm under high seller-concurrent-bootstrap load — the in-flight existence check causes serialization conflicts; Convex retries up to its standard ceiling, then either commits or returns HTTP 409. **Resolved:** the lock contract explicitly relies on Convex serializable-transaction model; the index `by_org_capability_lifecycle` keeps the existence check at p95 ≤ 50 ms; storm is bounded by Convex's OCC retry semantics. (b) Lock release races: AIOperation transitions to `accepted` at T0; a second `kb_bootstrap` invocation arrives at T0+1ms before the index is fully consistent. **Resolved:** Convex serializable transaction semantics — the lock-check transaction either reads the committed AIOperation row (lifecycle_state ∉ {processing, pending_outcome} → check passes) or doesn't see it yet (lifecycle_state = processing → check fails); no inconsistent intermediate state. (c) Re-bootstrap after rejection — the FreeAllowanceCounter re-credit window via §34.11.2 ContestRecord. **Resolved:** the lock check at the second invocation observes that the first AIOperation is no longer in flight; the re-credited allowance permits the new invocation.

2. **§22.8.4.8 `kb_entry_draft_create`.** (a) Agent calls `kb_entry_draft_create` without first calling `kb_dedupe_check` — server returns HTTP 422 `dedupe_gate_failed`. **Resolved:** input schema requires `dedupe_verdict` object; server rejects missing or `checked=false` payloads. (b) Agent fabricates `source_refs` to bypass provenance gate — server-side validation rejects when source-ref cannot be resolved against bootstrap Firecrawl-crawled URL set or ghost-RFP uploaded file hash. **Resolved:** the server-side validator cross-references `source_refs[].source_value` against the parent session's permitted source set (passed in JWT claim or fetched from §4.8.7 / §4.4.14 GhostBidImport row); fabricated source_refs return HTTP 422 `invalid_source_ref`. (c) 500-draft per-session write cap exhaustion mid-bootstrap. **Resolved:** the cap is enforced server-side; the 501st `kb_entry_draft_create` call returns HTTP 429 `per_session_draft_quota_exhausted`; the bootstrap agent emits `agent.message` and halts with a "manual review of remaining sources" prompt; the parent AIOperation settles per §21.4.5.

3. **§22.10.3.A concurrency lock spans Seller Org with split-region residency.** (a) Two seller users in the same Org but pinned to different residency regions (e.g., one US-pinned bid_workspace, one EU-pinned org-level setting) both invoke `kb_bootstrap`.
