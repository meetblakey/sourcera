## 2. Counterfactual Pass — Failure Modes the Spec Must Address

For §4.7.1 Console Bridge Event:
1. **Seller-side enumeration of row-level fields beyond `payload_json` reveals buyer-internal data.** Unhandled. → D-1.6-001 (P0).
2. **Ops re-drive of `dlq` event collides with a concurrent buyer-source mutation that emits a new event.** Conflict-Resolution block (line 7424) is silent on this race. The new event would write into `pending` while the re-drive transitions the older row to `pending` simultaneously; both rows then reference the same `(buyer_workspace_id, bid_workspace_id, event_kind, source_entity_id, source_entity_version)` only when the new mutation reuses the same source_entity_version (rare but possible if the buyer reverts). → D-1.6-008 (P2).
3. **Buyer-side mutation handler fails to bump `source_entity_version` between two consecutive amendments on the same Requirement.** The `(buyer_workspace_id, bid_workspace_id, event_kind, source_entity_id, source_entity_version)` idempotency key reuses; second emission returns HTTP 200 with the existing row id (per AC #10, idempotent replay) and the second amendment's content is silently dropped. The spec assumes monotonic source_entity_version but does not enumerate this as a failure mode. → noted in scratch; not promoted to a separate defect (the underlying invariant is documented in §4.3.3 Requirement state machine; the bridge entity's silent-replay behavior is intentional).
4. **`attachments_urls` carried in `qa_thread_post_appended` contains a buyer-uploaded file with internal scoring/comments.** The redaction validator only checks structural conformance; attachment content is unconstrained. → D-1.6-009 (P2).
5. **Convex Storage signed URL in `attachments_urls` expires before the seller renders it.** Not addressed; acceptable engineering assumption (signed URLs are time-bounded by Convex policy) but worth flagging if the URL-renewal contract differs across consoles.
6. **Kill-switch released while a `pending` event has already been re-superseded by a newer event.** §25.2.6 covers email suppression but not the supersede-during-pause race; the §4.7.1 superseded transition is from `pending` or `retrying`, both of which are paused under the kill-switch — so superseding still works but the new `pending` event is also paused. Acceptable per the spec's kill-switch semantics; no defect.

For §4.7.2 Vendor Disqualification Record:
1. **DSAR right-to-erasure on the `rationale_author_user_id` while the disqualification is still active.** Unhandled. The retention block says "PII fields redacted" but does not enumerate which fields, the pseudonymization sentinel, or the §6.8.4 cascade walker integration. → D-1.6-004 (P1).
2. **Global ban reversal does not enumerate cascade reversal for Marketplace Listings, SellerOrgPage 410 → restore, Capability Declarations forced `published=false` → restore, Seller Signal delivery resumption.** The Reversal block (line 7580) covers soft and account-level reversal cascades but global-ban reversal is silent. → D-1.6-010 (P2).
3. **Vendor's seller Org is deleted between disqualification creation and appeal-window expiry.** Failure Mode #4 covers vendor-Org-deleted-between-disqualification-and-appeal; the appeal flow is disabled with `appeal_status=not_offered`. Acceptable.
4. **Concurrent disqualification + scoring-cell submit on the same vendor.** Appendix I `scoring_cell_vendor_disqualified_concurrent` (HTTP 409) covers; AC handled.
